The eco-cycle

Every feature is a loop through one shared document. A screen calls the api client → a Fastify endpoint mutates the Itinerary (insert-only / non-destructive) → the write lands in Firestore → the client's edits store bumps a version → useAsync refetches → the screen (and the map behind it) updates. That single spine is why add-a-stop shows on the Day and the map, why a settled expense appears in Alerts, and why a shared companion sees the same trip.

Map-first 3D redesign

Requested. Match app-preview.html exactly (the night, map-first design); make the map a real Google-style 3D map; fix the "AJAX error" on map screens; and take the walking mannequin off the map.

Prerequisites & what was added

Google Places toggle + money gate

Requested. A Settings toggle to turn Google Places on/off anytime, and — most importantly — gatekeep every request so no money leaks.

Prerequisites & what was added

  • Server-side gate (the money control) — lib/settings.ts holds placesEnabled (default OFF); google.ts routes every Google call through one placesAllowed() check. Off → no network request, logged "request blocked (no spend)".

Why this direction

Putting the check at the single lowest chokepoint (the raw fetch guard) means no code path can ever reach Google around it connects → server/places/google.ts — new Places features inherit the gate for free.
