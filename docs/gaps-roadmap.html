Wayfare · Gaps & Roadmap

What we've built, and the one thing we haven't

The read path is solid and connected. But the app's whole reason to exist — an AI that generates guided itinerary proposals from what you ask for — isn't built yet. Here's the honest map of the gap, and the order I'd close it in.

The reframe

Today Wayfare is an excellent viewer of itineraries we hand-seed. Its purpose is to be a generator: ask for a trip → Claude proposes three, you shape them, it writes the block-by-block schedule. Everything we've done is the destination the generator should produce — we just haven't built the generator.

Is the alarm working?

No. "1 hour and 15 min before" is just label text in Profile & onboarding. There's no expo-notifications, no scheduling — nothing fires. The 15/5-min reminders, and the skip-to-extend button, need to be built.

no — not implemented

Real-time distance/ETA to the next place?

No. There's no expo-location; the map screen is a hand-drawn SVG, and "1.4 km · 6 min from you" is hardcoded. Live "how far am I" needs device GPS + a distance/ETA calc that updates as you move.

partial — L3 missing

Layers 1 (Day list) and 2 (whole-day timeline) exist. Tapping a block opens Maps, but there's no dedicated detail screen with the full write-up + embedded map + "Open in Google Maps". That's a clean, quick build.

Animation, kept lightweight

You already ship react-native-reanimated — that carries most of it for free. Add exactly one vector-animation library for the few "hero" moments (like a traveler who actually walks). My pick order:

Micro-interactions → Reanimated

Already installed, GPU-driven, ~0 added weight. Use for: screen transitions, staggered day reveals, the skip→extend morph, progress fill on the live "up next" card, button springs.

→ use everywhere, no new dep

The walking traveler → Rive

Modern successor to Lottie: tiny runtime, real-time state machines so the walker can speed up as your ETA shrinks. Web + native renderers. Best "latest tech, still light".

→ recommended for hero moments

Fast path → Lottie

If Rive's a bigger lift than you want: lottie-react-native plays free JSON walk-cycles today. Mature, lightweight, but not interactive.

→ easiest, non-interactive

Recommended build order

Purpose-first: make the app do its job, then make the day-of experience live, then polish. Each phase ends in something demoable.

1

The generator the whole point

Turn the mock wizard into the real thing: POST /api/generate calls Claude server-side (key never in the app), returns 3 proposals in our schema; a 2nd call writes the block timeline; Save persists via new write routes.

  • Server: /api/generate, /api/itineraries (POST/PATCH), Claude client
  • App: wire create/* steps to real state → generate → review → save
  • Guardrail: proposals stay coherent/connected (like the seeded trips), work-blocks & nap windows respected
2

Layer 3 + real map quick win

New activity/[id] detail screen with the full write-up, per-person status, meal & cost, an embedded map, and "Open in Google Maps". Swap the stylized map for a real embed.

  • No schema change — the data's already there
  • Deep link via the existing openMaps()
3

Live day day-of magic

Device GPS → "how far to the next place" that updates as you move; the "up next" card goes live.

  • expo-location + distance/ETA, throttled updates
  • The walking traveler animates toward the next stop (Reanimated/Rive)
4

Reminders + skip/extend the alarm

Real notifications 1h / 15m / 5m before each block (editable in Reminder Settings), and a Skip that extends your current block and reflows the rest from where you are now.

  • expo-notifications scheduling tied to activity times + travel buffer
  • Reflow logic recomputes downstream blocks live
5

Import, auth & polish completeness

Bring existing plans in (POST /api/import reusing the extractor), Firebase auth + ownerId, fix the Home tab to render live, and the animation pass across the app.
